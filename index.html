Dataset columns: age, income, tenure (numeric) · city (categorical) · target churn. Models: random_forest, decision_tree, logistic_regression, knn.

How the compiler works

1 · Lexer

Scans characters into six token classes with line and column positions; rejects illegal characters and unterminated strings.

2 · Parser

Recursive descent, one function per grammar rule, building a typed AST. Stops at the first syntax error with a caret.

3 · Semantic analysis

Checks stage order, column existence and types, split validity, model hyperparameters and metrics, then adds warnings.

4 · IR optimizer

Fuses preprocess blocks, removes duplicate steps and enforces fill → scale → encode ordering.

5 · Code generation

Emits a scikit-learn script using ColumnTransformer and Pipeline, so preprocessing is fitted on training data only.

6 · Execution

Trains and evaluates the IR in the browser on a seeded synthetic dataset; Compare models re-runs it with all four models.

Grammar

program    ::= pipeline
pipeline   ::= 'pipeline' ID '{' stmt* '}'
stmt       ::= load | preprocess | split | model | 'train' ';' | evaluate
load       ::= 'load' 'data' STRING ';'
preprocess ::= 'preprocess' '{' ( ('fill_missing'|'scale'|'encode') ID ';' )* '}'
split      ::= 'split' 'train' NUM 'test' NUM ';'
model      ::= 'model' ID '{' ( ID '=' NUM ';' )* '}'
evaluate   ::= 'evaluate' 'metrics' '[' ID (',' ID)* ']' ';'
Pipeline: Source → Lexer → Parser → AST → Semantic analysis → IR optimizer → Python (scikit-learn) code generation → execution. Everything runs client-side; no server.
